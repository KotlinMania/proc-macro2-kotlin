# Debug formatting contract

The source is pinned to dtolnay/proc-macro2 revision `58ab776b95a4c2865554badbb6629c50971a9118` (1.0.106), covering the Debug implementations in `src/lib.rs` and their compiler/fallback dispatch. The existing Kotlin artifact exposes span locations unconditionally, so formatting includes nontrivial location fields.

Rust `Debug::fmt` for TokenStream, TokenTree, Group, Punct, Ident and Literal maps to typed Kotlin `debug(alternate: Boolean = false)` extensions on those same six types in `io.github.kotlinmania.procmacro2`. `alternate` carries the formatter's alternate flag. This follows the existing Kotlin Syn Debug operation mapping and distinguishes Debug output from the existing Display operation, `toString()`. It adds no aliases, reexports or replacement token types. The returned String owns the output. Compact and alternate formatting preserve the structured fields, recursively format groups, omit trivial fallback spans, and retain compiler span diagnostics. Formatting clones a stream before iteration, preserving its contents.

No existing declaration is renamed or removed, and Display output is unchanged. The extensions are additive source APIs; consumers using them must compile against the new library artifact. Existing source calls and binary declarations retain their signatures. `RUST_CALLERS.md` lists token-type callers; no existing cross-repository import or invocation changes for this additive operation. It does not establish generic Debug trait interoperability or disabled-feature variant parity.

The two previously empty ignored Debug tests now compare actual compact identifier output and the complete upstream alternate token-stream output, including locations. The test also checks empty streams and confirms formatting leaves Display output intact. The upstream feature test is itself ignored. Its previous Kotlin body asserted a fixed false constant unrelated to compilation. That fake body is replaced with the required semantic-gap comment at the original source location: Kotlin has no compiler-bridge-disabled build variant. Removing that nonexecuting constant assertion does not establish feature parity; the Cargo acceptance report records the missing build variant explicitly.
